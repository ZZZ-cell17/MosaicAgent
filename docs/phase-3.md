# 第三阶段记录：可观测单 Agent 运行时

## 目标

将第二阶段跑通的 MRAG 闭环升级为有明确边界、稳定接口、失败降级和完整运行轨迹的单 Agent，同时保持项目只聚焦多模态知识问答。

## 对原项目的继承

以下核心链路来自 JoyAgent-JDGenie MRAG，并继续作为 Agent 的决策骨架：

- 判断问题是否需要知识库
- 查询扩展与图片辅助查询扩展
- 文本稠密、BM25、图片稠密、页面稠密四路并行检索
- 子问题证据摘要
- 证据充分性判断与查询改写
- 多轮检索、结果去重、文本重排
- LLM/VLM 答案生成

## 本阶段工程化

- 新增供应商无关的 Agent SSE 事件协议和每次请求唯一 `run_id`
- 四路检索分别记录命中数、耗时、状态和错误类型
- 查询行规范化、去重，并限制每轮子查询数量
- 摘要上下文按文本块去重并限制数量，控制 Token 成本
- 加固普通 JSON、Markdown JSON 代码块的结构化解析
- 显式记录证据充分性、查询改写、停止原因和检索轮数
- 根据问题与证据类型动态选择 LLM/VLM
- 返回文本、图片或页面的结构化引用
- 单路检索失败继续运行，Reranker 失败回退到召回顺序
- 无知识库证据时使用受约束拒答，四路检索全失败时返回安全错误事件
- 保留原始 `AgenticRAG.run()`，供只消费模型 chunk 的内部调用兼容使用

## 验收结果

- `uv run pytest -q -p no:cacheprovider`：17 项测试通过
- Python 编译检查通过
- `git diff --check` 通过
- 本地服务 `/ready`：存储和五类模型配置全部 ready
- 使用 `mosaic-demo` 真实查询：第一轮生成 2 个查询；文本稠密命中 20、BM25 命中 20、页面命中 2、图片命中 0；证据判断充分；Reranker 保留 2 个文本引用；路由选择 LLM；最终产生 `run_completed`
- 使用明确依赖架构图视觉布局的真实查询：页面命中 1；动态路由选择 VLM；实际使用 1 个页面视觉证据；返回 `text,page` 两类引用和 2294 个回答字符；达到最大检索轮数后按边界正常生成并完成

## 当前边界

- 仍是单 Agent，不包含原项目的多 Agent 任务编排
- 不保存跨请求对话记忆
- 当前本地 Qdrant 模式面向单进程运行；多进程部署需切换到 Qdrant Server
- 评测集、容器化、持续集成、前端产品界面和生产监控属于后续工程化阶段
